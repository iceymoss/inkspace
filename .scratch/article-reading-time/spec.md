# 博客文章预计阅读时长

Status: ready-for-agent

**Progress:** 两票的实现和验收检查已完成：隔离 MySQL/Redis 下验证历史详情的缓存命中/未命中不回写、创建与编辑后的缓存失效，以及知识库发布/重新发布；HTML 块可见文字已补计。完整 Go 检查和博客前端测试、lint、构建已通过；待代码评审和提交。

## Problem Statement

读者打开博客文章详情时无法判断阅读正文大约需要多久。文章已有 `reading_time` 字段，但现有保存流程并未填充，历史文章也可能存有零值；直接显示字段会出现无意义的「约 0 分钟阅读」。

## Solution

在博客文章详情页标题下方的元信息区域显示「约 N 分钟阅读」。N 是根据文章正文估算、对所有读者相同的预计阅读时长，不是读者实际花费的时间。新建与编辑博客文章时计算并保存到已有字段；历史文章字段为零时仅在详情展示时临时计算，不回写数据库或缓存。知识库文档自身不增加时长统计。

## User Stories

1. 作为博客读者，我希望在文章标题下方看到预计阅读时长，以便安排阅读时间。
2. 作为博客读者，我希望同一文章的预计阅读时长不随读者身份或浏览行为变化，以便把它理解为内容估算而非个人记录。
3. 作为博客读者，我希望历史文章也能显示有意义的预计时长，而不是零分钟。
4. 作为作者，我希望新建文章时自动保存预计阅读时长，无须填写或维护额外字段。
5. 作为作者，我希望编辑文章后预计时长依据最新正文更新，即使之前的字段为零。
6. 作为管理员，我希望经管理入口创建或编辑的文章遵循同一规则。
7. 作为将知识库内容发布为博客文章的作者，我希望生成的博客文章遵循文章预计阅读时长规则，同时不改变知识库文档自身的统计。
8. 作为读者，我希望中文、英文及数字混排的文章时长按各自文本量合理估算，而非被 Markdown 标记或长 URL 拉高。
9. 作为读者，我希望只有图片或极少文字的文章至少显示一分钟，而不是零分钟。
10. 作为维护者，我希望浏览历史文章不会暗中修改其数据库记录或缓存数据。

## Implementation Decisions

- 只以博客文章**正文**估算；不计文章标题、作者、标签、评论等正文外信息。正文中的 Markdown 标题、引用、列表、链接显示文字、图片替代文字和代码文字视为可读文字；不计 Markdown 标记、链接地址、图片地址或图片本身的额外耗时。自动链接 URL 和原始 HTML 标记不作为可读正文计入。
- 汉字按 300 字/分钟，其余英文及数字按连续词段计数、200 词/分钟；两个时间相加后向上取整，至少 1 分钟。空正文沿用至少 1 分钟的展示规则。
- 文章创建和编辑统一在博客文章业务保存路径计算并持久化到现有 `reading_time` 字段；用户、管理员及知识库发布成博客文章的路径均适用。请求体不要求调用方提交估算值，不新增数据库字段。
- 文章详情优先使用已保存的非零 `reading_time`。历史文章值为 0 时在**详情响应**计算回退值，不修改文章实体、数据库或 Redis 缓存。缓存命中和数据库读取必须呈现同样结果；其他响应（如列表或编辑页）不作历史数据回填。
- 仅在博客文章详情页元信息区域新增中文文案；不改知识库文档的字数统计、详情页、存储结构或其已有业务语义。

## Testing Decisions

- 以用户可观察行为为验收目标：详情响应对已保存值直接显示，对历史零值返回正确估算值而不改变原始记录；覆盖缓存命中和数据库读取时临时回退不能污染持久层或缓存。
- 在文章保存路径验证新建、编辑均写入按当次正文计算的值，且用户、管理员和知识库发布为文章复用相同规则。优先使用已有不依赖真实 MySQL/Redis 的测试方式；需要数据库和缓存才能覆盖的交互使用隔离的测试服务或明确列为手工端到端验证，不能污染开发数据。
- 在纯计算边界用表驱动测试覆盖：空/极短正文、中文和英文各自整分钟边界、混排时间相加与向上取整、数字词段、标题/引用/列表、链接显示文字与目的地址、图片替代文字与地址、行内/围栏代码、自动链接和原始 HTML。
- 验证博客详情页元信息区域出现「约 N 分钟阅读」，知识库详情与统计不变。全量执行 Go 测试、静态检查和构建，以及博客前端 lint 和构建；具备隔离 MySQL/Redis 时再做真实存取及缓存验证。

## Out of Scope

- 知识库文档自身的阅读时长与既有字数统计修改。
- 为历史文章批量回填数据库、详情读取时写库或更新缓存中的历史零值。
- 按读者阅读行为跟踪实际阅读时间，或由前端按个人阅读速度估算。
- 新增字段、数据库迁移、国际化、文章列表和编辑页展示历史估算值。

## Further Notes
