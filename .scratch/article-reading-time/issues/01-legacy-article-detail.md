# 01: 历史博客文章详情展示预计阅读时长

**What to build:** 读者在博客文章详情页的元信息区域看到「约 N 分钟阅读」。现有文章即使尚未存储时长，也能按正文的可读文字计算预计分钟数并显示；读取历史文章不会修改数据库或缓存中的原值。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

**Progress:** 实现与验收检查已完成：HTML 块内可见文字已补计，历史文章详情在隔离 MySQL/Redis 的缓存未命中、命中场景下均验证了响应估算且不回写 `reading_time`；完整 Go 测试、vet、构建及博客前端测试、lint、构建通过。待代码评审和提交。

- [x] 使用约定的中文 300 字/分钟、其余英文及数字 200 词/分钟的混排合计和向上取整规则，至少 1 分钟；只计正文 Markdown 中可读文字，不计语法、链接/图片地址或图片额外时间。
- [x] 详情响应优先保留已存储的非零值，零值时临时估算；无论数据库读取还是缓存命中都不写回估算值。其他文章响应不做历史回填。
- [x] 博客文章详情页标题下现有元信息区域显示该值；知识库详情与统计不变。
- [x] 以详情行为及纯计算边界的测试覆盖混排、Markdown 和历史回退；运行相关 Go 测试和博客前端检查。
- [x] 复核当前工作区已有的未提交预实现及测试，不将其视为已完成或自动通过验收。
