# 系统初始化与首位管理员

Status: completed

## Problem Statement

新部署的 InkSpace 启动后会自动创建公开的默认管理员账号与密码。部署者不能在管理后台自行设定首位管理员，默认凭据也有被他人利用的风险。仅依据当前是否存在管理员来决定开放注册，会在管理员被降级、停用或删除后错误地重新开放入口；仅凭用户表是否存在，又会把先启动博客服务的新部署误认为旧系统。系统必须在启动时核对持久初始化状态与管理员账号，并保证后台操作不会让系统失去最后一位可登录管理员。

## Solution

新版本进程启动、连接数据库时核对系统初始化状态和管理员账号；全新安装进入“待初始化”状态，而升级自已有数据的部署保持关闭初始化入口。部署者在管理后台初始化页面输入仅自己持有的初始化密钥，以及自行设定的用户名、邮箱、密码与确认密码。后台核验密钥并原子创建首位管理员和完成初始化状态；之后只能登录，不再允许初始化。已初始化但管理员不可用时不开放网页恢复。最后一位可登录管理员不能通过后台被降级、停用或删除；角色或状态变更后旧后台令牌立即失去权限。博客的公开访问与普通用户注册保持原有行为。

## User Stories

1. 作为新部署者，我希望系统启动时识别待初始化状态，而不是自动生成默认管理员，以便自行设置安全的账号凭据。
2. 作为新部署者，我希望先启动博客、后台或调度器都能正确识别全新安装，以便不受启动顺序限制。
3. 作为管理者，我希望首次访问管理后台看到系统初始化页，以便在网页上创建首位管理员。
4. 作为管理者，我希望在初始化页输入用户名、邮箱、密码及确认密码，以便掌握首位管理员的凭据。
5. 作为部署者，我希望初始化需要服务器侧配置的独立密钥，以便陌生访客不能抢先成为管理员。
6. 作为部署者，我希望未配置密钥时后台显示初始化暂不可用并拒绝提交，以免无保护地开放创建入口。
7. 作为部署者，我希望初始化密钥不返回浏览器、不写入日志或仓库，以免泄漏。
8. 作为管理者，我希望成功创建首位管理员后进入登录流程，以便用自己设置的凭据登录。
9. 作为管理者，我希望用户名或邮箱被已有普通用户占用时得到提示并另选凭据，而不是把对方升级成管理员。
10. 作为管理者，我希望密码确认或输入校验失败时能修正表单，且系统仍保持待初始化。
11. 作为维护者，我希望创建首位管理员和记录初始化完成同时成功或同时失败，以免产生半成品状态。
12. 作为维护者，我希望并发提交时至多创建一位首位管理员，以免多人通过初始化获得权限。
13. 作为管理员，我希望完成初始化后公开入口永久关闭，即便初始化密钥仍留在环境中，以免再次创建管理员。
14. 作为旧系统维护者，我希望升级后现有管理员保留、不被重置，且初始化入口保持关闭，以便不中断原有访问。
15. 作为旧系统维护者，我希望无初始化记录但已有旧用户数据、甚至当前没有管理员时仍不开放网页初始化，以免历史角色变更触发抢注。
16. 作为维护者，我希望已初始化但没有可登录管理员时系统提示异常而不是重新开放网页入口，以便通过受控的服务器/数据库流程处理。
17. 作为管理员，我希望最后一位可登录管理员不能被降级、停用或删除，以便后台始终有人可以管理。
18. 作为管理员，我希望已停用或已删除的管理员不被算作可接替者，以免误判最后一位可登录管理员。
19. 作为管理员，我希望在确有其他可登录管理员时仍能按后台管理规则调整账号，以便正常管理成员。
20. 作为管理员，我希望被降级、停用或删除的账号所持旧后台令牌立即失效，以免继续使用管理员权限。
21. 作为读者，我希望系统待初始化时公开博客仍可访问，以便不受后台配置影响。
22. 作为普通用户，我希望待初始化期间仍能按照既有规则注册普通账号，且不会因此取得管理员权限或阻碍初始化。
23. 作为维护者，我希望部署说明解释密钥设置、旧默认账号的风险和状态异常的恢复边界，以便安全上线及升级。

## Implementation Decisions

- 启动阶段（数据库迁移建表前及建表后）负责判定安装来源与初始化状态，不把“打开页面”当作首次安装的判断时机。三个共用数据库的程序以同一持久记录协调，不依赖启动顺序或单个进程的内存状态。启动检查失败时不能默认为待初始化。
- 首次启动前可以预先创建空数据库，但不能预建业务表。首次检查时，除受保护的初始化状态表外存在任何基础表，都视为旧安装并永久关闭网页初始化；不依据表内是否已有记录做宽松推断。初始化来源检查、互斥锁、迁移或一致性检查任一步失败时，对应进程必须启动失败。运行期间状态查询失败时返回不可用，不能开放初始化。
- 引入受保护且持久的系统初始化记录，不使用可由普通后台设置 CRUD 修改、删除或公开读取的通用设置项。状态与账号共同判定：新安装无记录且无历史数据 → 待初始化；无记录但有旧用户表/管理员数据 → 视为旧安装，不开放初始化并记录或呈现安全状态；有完成记录且有管理员 → 已初始化；有完成记录但无管理员或无可登录管理员 → 异常、仍不开放初始化。已有停用或软删除的历史管理员不能让旧库重新进入待初始化。需要保留足够信息来区分“新版本首次启动时尚无表”和“旧库迁移后没有管理员”。
- 移除启动时自动创建 `admin / admin123` 的逻辑和无条件输出默认凭据的日志；不自动覆盖、重置或删除旧系统的管理员账号。旧部署保留原状，部署文档提醒立即处理旧默认密码。
- 后台提供未认证的初始化状态查询（只返回对用户有用的有限状态，不泄露密钥或账号数据）和受密钥保护的首位管理员创建接口。管理后台根据状态将待初始化用户引导至初始化页；已初始化的用户走既有登录页，异常或密钥未配置时给出不能继续的提示。服务端始终重新核查状态和授权，不能信任浏览器的页面跳转。
- 初始化密钥由部署者在服务器环境中配置，不能使用仓库内的默认值；必须由至少 32 个随机字节生成。未配置或不正确时拒绝创建。创建成功后不论密钥是否还在环境中，接口都拒绝再次创建。部署文档提示删除不再需要的密钥。密钥不是管理员密码。初始化只能通过 HTTPS 或受控私网提交；应用和标准部署不得记录请求体或密钥。标准反向代理部署应对初始化提交限速，应用本次不引入依赖 Redis 的分布式限流。
- 创建首位管理员时校验用户名、邮箱、密码和确认密码，按现有密码哈希及账号约束存储；密码必须为 6–50 个 Unicode 字符，且 UTF-8 编码不得超过 bcrypt 的 72 字节上限，超限应作为明确的输入错误返回。只创建新账号，不升级占用用户名或邮箱的普通账号。账号写入与状态转换处于同一事务；跨进程并发提交只有一方成功，其他请求不得额外创建管理员。初始化失败不应留下可登录的管理员或“已完成”状态。
- 用户角色、状态与删除路径用服务端原子检查保护最后一位未软删除、状态为启用、角色为管理员的账号；并发请求也不能分别把两位管理员移除而留下零位。后台对用户的已有权限边界不放宽。
- 管理后台鉴权不能只信任 JWT 中的旧角色：每次使用管理员权限时需确认对应账号当前仍存在、启用且角色为管理员。被降级、停用或删除后，旧令牌立即失效。仅作用于后台授权，不扩大普通博客用户注册权限。
- 仅支持 MySQL；如引入破坏性约束或数据迁移，先与用户确认并提供可重复执行的迁移 SQL。状态记录及旧库判定必须兼容现有数据库，不破坏已有账号。

## Testing Decisions

- 以外部可观察行为而非私有函数调用为验收依据。主要测试边界为管理后台 HTTP：状态查询、初始化提交、认证和管理员角色/状态/删除操作；对需要真实持久化保证的行为使用隔离 MySQL 测试库，而非开发数据库。
- 覆盖全新安装及三程序不同启动顺序、无密钥/错密钥/正确密钥、表单无效、用户名或邮箱冲突、重复及并发初始化；核对数据库中恰有一位新管理员且状态原子完成。测试旧库有活跃、停用或软删除管理员，以及旧用户表存在却无管理员、已初始化但无管理员/无可登录管理员等状态，确认不会重开入口。验证数据库查询失败不会被当成待初始化。
- 启动协议测试必须区分“共享函数顺序调用”和真实的独立数据库连接并发：至少使用多个数据库连接并发执行首次启动协议，验证互斥锁和唯一持久状态。旧库升级测试不得预建初始化记录，应从旧业务表直接执行完整启动协议。数据库失败测试至少覆盖一次真实 SQL 查询或互斥锁失败，不能只用空数据库句柄代替。
- 密码边界测试同时覆盖 Unicode 字符数与 UTF-8 字节数，特别验证字符数合法但超过 72 字节的密码被作为输入错误拒绝。部署文档验收需覆盖随机密钥生成、HTTPS 或受控私网、请求日志保护、反向代理限速及初始化后的密钥清理。
- 覆盖一位及两位可登录管理员的降级、停用、删除与并发变更，确认最后一位始终保留；使用旧令牌请求受保护路由，确认角色或状态改变后立即被拒。覆盖待初始化期间普通博客功能及普通注册不赋予管理员角色。
- Go 测试沿用标准库 `testing`、Gin/`httptest` 路由和 handler 测试；数据库真实事务及 MySQL 专有行为沿用现有环境变量门控的隔离 `_test` 数据库集成测试，不能污染开发数据，也不能拿 SQLite 代替。自动测试无法运行时应明确报告未验证项。
- 为管理后台引入前端自动化测试工具，参照博客前端的 Vue 组件测试模式，覆盖路由跳转、初始化表单校验与成功/失败反馈；以 mocked API 测页面行为，不把前端测试当成后端安全证明。运行管理后台测试、lint（注意现有命令会自动修复）及生产构建，并运行全部 Go 测试、vet 和构建。

## Out of Scope

- 从公开网页恢复遗失的管理员权限、自动重置已有管理员账号、自动为旧库补建首位管理员。
- 改变普通用户注册策略、公开博客的现有功能、引入多语言或新的前端 UI 框架。
- 将初始化密钥作为日常登录凭据或长期的“额外管理员”入口。

## Further Notes

- “系统初始化”在启动时核对状态；网页是管理者完成首位管理员创建的入口，不是决定系统是否首次运行的信号。
- 旧版本用户表没有“曾为管理员”的历史角色记录；因此旧表存在且缺乏初始化记录时不能仅凭当前无管理员就开放初始化。
- 任何人直接更改数据库、数据库损坏或所有管理员忘记密码的情况，无法只靠后台的最后一位管理员保护消除；需要在部署说明中记录仅由有服务器/数据库权限的维护者执行的受控恢复方式，不能重新开放公开初始化入口。
