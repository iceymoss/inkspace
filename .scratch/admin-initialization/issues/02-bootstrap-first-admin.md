# 02: 启动检查并由管理后台创建首位管理员

**What to build:** 新部署启动时识别待初始化状态，不再自动创建默认管理员；管理者首次访问后台时通过受密钥保护的页面设置首位管理员。旧部署与异常状态不开放初始化，成功后只能登录，公开博客保持原有行为。

**Blocked by:** None (can start immediately). 建议在 01 完成后实施以便首位管理员随即获得完整的安全保护，但 01 不是功能上必须完成的前置条件。

**Status:** completed

- [x] 新安装无论先启动博客、后台还是调度器，都在启动检查后判定为待初始化；页面打开不负责首次安装判定，不再自动创建或记录 `admin / admin123` 凭据。
- [x] 旧库有管理员（含停用或软删除历史管理员）时保留账号、不重置凭据且不开放初始化；旧用户表存在但无管理员、完成记录存在但无可登录管理员、数据库查询出错时也不开放初始化。
- [x] 管理后台未认证状态接口只提供必要信息，待初始化时显示初始化页面；密钥缺失时页面提示不可用、后端拒绝创建；博客公开访问及按原有规则注册普通用户不受影响。
- [x] 管理者输入初始化密钥、用户名、邮箱、密码、确认密码；密钥正确且输入有效时创建新的首位管理员，并与初始化完成记录在同一事务中提交，然后引导登录。
- [x] 错误密钥、无效表单、被普通用户占用的用户名或邮箱都不能创建管理员；不自动升级已有账号，不向浏览器或日志泄露密钥。
- [x] 重复、并发提交至多成功一次；即使环境中保留密钥也不重新开放入口。失败或异常不会产生部分完成的状态。
- [x] 管理后台有自动化测试覆盖路由引导、表单校验及提交成功/失败反馈；后端 HTTP 及隔离 MySQL 测试覆盖启动判定、并发与旧库；部署说明涵盖密钥、旧默认密码风险和需要服务器/数据库权限的受控异常恢复。
- [x] 运行全部 Go 测试、vet、构建，以及管理后台前端测试、lint 和生产构建；无法运行的隔离数据库验证如实标注。
