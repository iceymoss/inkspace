# 03: 收紧系统初始化安全契约并补齐验收证据

**What to build:** 部署者获得边界明确且可验证的系统初始化流程：旧库判定和启动失败遵循保守规则，合法密码与 bcrypt 字节上限一致，初始化密钥具备明确的生成、传输、日志和限速要求；自动化测试能够证明多连接并发启动、真实旧库升级和数据库失败都会安全关闭初始化入口。

**Blocked by:** 01: 保护最后一位可登录管理员并即时撤销后台权限；02: 启动检查并由管理后台创建首位管理员。

**Status:** completed

- [x] 首次启动前允许预建空数据库但不允许预建业务表；存在任何既有业务基础表时按旧安装处理，完整启动协议从没有初始化记录的旧库生成关闭状态且不改变已有管理员。
- [x] 初始化来源检查、互斥锁、迁移或一致性检查失败时进程启动失败；运行期状态查询发生真实数据库错误时返回不可用，绝不进入待初始化。
- [x] 使用独立数据库连接并发执行首次启动协议，验证 MySQL 互斥锁下只产生一条持久初始化记录；测试说明不再把同进程顺序调用表述为三个真实程序启动。
- [x] 首位管理员密码限制为 6–50 个 Unicode 字符且 UTF-8 编码不超过 72 字节；字符数合法但字节超限时前后端给出明确输入错误，不产生管理员或完成状态，并有多字节边界回归测试。
- [x] 部署文档要求初始化密钥由至少 32 个随机字节生成，只通过 HTTPS 或受控私网提交，应用和标准部署不记录请求体或密钥，标准反向代理对初始化提交限速，完成后清理密钥。
- [x] 更新规格与历史工单中的验收措辞，使其准确区分已有证明和本工单新增证明；运行相关 MySQL 集成测试、全部 Go 测试、vet、构建，以及管理后台测试、lint 和生产构建。

**验证（2026-10-23）：** 在临时 MySQL 8 容器的独立 `inkspace_bootstrap_startup_test`、`inkspace_bootstrap_test` 和 `inkspace_admin_guard_test` 数据库中运行启动、初始化和最后管理员门控集成测试，覆盖独立连接并发启动、无初始化记录的旧库升级、连接及真实 SQL 查询失败、密码字节边界和管理员并发保护，全部通过。带上述隔离数据库环境运行 `go test ./... -count=1` 通过；`go vet ./...`、`go build ./...`、管理后台 `pnpm lint`、`pnpm test`（16 项）和 `pnpm build` 通过。Nginx 配置语法检查未运行：本机没有 `nginx`，拉取校验镜像时 Docker Hub 连接重置。
