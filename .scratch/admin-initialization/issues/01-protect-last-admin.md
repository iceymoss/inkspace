# 01: 保护最后一位可登录管理员并即时撤销后台权限

**What to build:** 管理员在后台变更账号角色、状态或删除账号时，系统始终保留至少一位可登录的管理员；管理员权限被撤销后旧令牌立即无法再使用后台。行为可通过后台接口和隔离 MySQL 测试验收。

**Blocked by:** None (can start immediately).

**Status:** completed

- [x] 唯一可登录管理员被降级、停用或删除时，后台拒绝操作且账号仍可登录；停用、已删除管理员不算可接替者。
- [x] 存在其他可登录管理员时，后台按原有权限规则允许正常调整管理员角色、状态和删除；操作后至少仍有一位可登录管理员。
- [x] 两个可登录管理员受到并发降级、停用或删除时，不会留下零位可登录管理员；数据库中可观察到的结果与接口响应一致。
- [x] 被降级、停用或删除的管理员现有后台令牌立即失去访问受保护路由的能力；未变更的管理员正常访问。
- [x] 使用 HTTP 行为测试与受保护的隔离 MySQL 集成测试验证；不污染开发库，并运行相关 Go 测试、vet 和构建。

**验证（2026-10-21）：** 在专用 `inkspace_admin_guard_test` 数据库运行 `go test ./internal/router -run 'Test(AdminUser|ConcurrentAdminUser)' -count=1 -v`，包含并发请求结果与数据库最终状态的对照，全部通过。`go test ./... -count=1`、`go vet ./...`、`go build ./...` 通过（未设置测试 DSN 时完整测试中的隔离 MySQL 用例会跳过）。
